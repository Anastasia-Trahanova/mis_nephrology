1. Назначение приложения

«МИС Нефролога» — медицинская информационная система, предназначенная для автоматизации повседневной работы врача-нефролога. Приложение используется для организации приёма пациентов, ведения медицинской документации, хранения клинических данных, контроля динамики состояния пациента и автоматического расчёта основных нефрологических показателей.

Система ориентирована прежде всего на врачей-нефрологов, которые проводят первичные и повторные консультации пациентов с заболеваниями почек, включая пациентов с хронической болезнью почек. Приложение объединяет основные этапы работы врача в едином интерфейсе: от просмотра расписания и выбора пациента до оформления результатов приёма, формирования рекомендаций и выгрузки медицинского документа.

Приложение включает следующие основные функциональные модули:

Модуль расписания для просмотра рабочего графика врача и запланированных обращений пациентов. При открытии раздела система автоматически показывает расписание вошедшего в систему врача. Записи распределяются по датам и времени, что позволяет заранее оценить нагрузку и последовательно работать с пациентами в течение рабочего дня.

Модуль списка приёмов позволяет просматривать ранее созданные медицинские записи. Для поиска нужных сведений могут применяться фильтры по периоду, врачу, филиалу, отделению и данным пациента.

Модуль электронной медицинской карты (ЭМК) пациента объединяет основные сведения о пациенте и историю его наблюдения. В ЭМК отображаются персональные данные, перечень проведённых приёмов, результаты осмотров, лабораторных и инструментальных исследований, диагнозы, назначения и рекомендации. Можно выбрать конкретный приём, просмотреть сохранённую в нём информацию и перейти к оформлению следующего обращения.

Модуль первичного приёма предназначен для внесения медицинской информации. Форма приёма включает жалобы пациента, анамнез заболевания и жизни, объективный статус, физикальные данные, сведения о сопутствующих заболеваниях, результаты лабораторных и инструментальных исследований, диагнозы по МКБ-10, лекарственные назначения, рекомендации, диету и дату следующего визита.

При оформлении повторного приёма часть сведений из последней медицинской записи пациента загружается автоматически. Это исключает повторный ввод неизменившейся информации. Предзаполненные значения можно актуализировать с учётом состояния пациента на текущем приёме.

Расчётный модуль автоматически определяет нефрологические показатели на основании введённых исходных данных. В системе предусмотрены расчёты индекса массы тела, скорости клубочковой фильтрации по CKD-EPI 2021 и по формуле Кокрофта-Голта, стадии хронической болезни почек, отношения альбумина к креатинину мочи, категории альбуминурии и прогностической категории риска по KDIGO. Результаты расчётов формируются программой и не предназначены для ручного изменения.

При заполнении форм система контролирует обязательные поля, даты и допустимость вводимых значений. Сообщение о проблеме отображается рядом с соответствующим полем до сохранения записи. Это помогает своевременно исправить техническую ошибку ввода и уменьшает вероятность сохранения неполных или противоречивых данных.

После сохранения приёма информация включается в общую историю наблюдения пациента. Выбранный приём можно экспортировать в документ Microsoft Word для последующего просмотра, печати или использования в установленном медицинской организацией порядке.

2. Доступ к системе и начало работы

2.1. Условия доступа и создание учётной записи

«МИС Нефролога» является веб-приложением. Работа с системой выполняется в браузере, установка на рабочий компьютер врача не требуется.

Для доступа к приложению необходимы:

  • компьютер или ноутбук с веб-браузером;
  • подключение к локальной сети медицинской организации или другой сети, в которой размещён сервер приложения;
  • адрес приложения, предоставленный администратором или техническим специалистом;
  • действующая персональная учётная запись;
  • логин и пароль для входа в систему.

Адрес приложения зависит от способа его размещения. При локальном запуске на компьютере разработчика может использоваться адрес вида http://127.0.0.1:8000. При размещении приложения на сервере медицинской организации используется внутренний сетевой адрес или доменное имя, предоставленное ответственным специалистом.

Для корректной работы рекомендуется использовать актуальную версию браузера Google Chrome, Microsoft Edge, Mozilla Firefox или другого браузера, поддерживающего современные веб-технологии. В браузере должны быть разрешены JavaScript и файлы cookie для работы интерактивных элементов и сохранения пользовательской сессии.

Доступ к медицинским сведениям предоставляется только после успешного входа. Без действующей пользовательской сессии внутренние страницы приложения не открываются. При попытке перейти на защищённую страницу пользователь автоматически перенаправляется на страницу входа.

Самостоятельная регистрация пользователей в приложении не предусмотрена. Учётная запись создаётся администратором базы данных, разработчиком или другим специалистом, сопровождающим приложение. Пользователь передаёт ответственному специалисту сведения, необходимые для создания учётной записи и назначения роли.

Для врача до создания учётной записи в системе должна существовать запись о нём как о медицинском работнике. Она содержит фамилию, имя, отчество, должность, сведения об образовании и профессиональной переподготовке, сертификате и квалификации, а также номер телефона врача. Отдельно запись врача связывается с одним или несколькими местами приёма. После этого создаётся пользовательская учётная запись с ролью «Врач».

По связке учётной записи с соответствующей записью врача приложение автоматически определяет, какой врач вошёл в систему для того, чтобы:

  • в расписании по умолчанию открывалось расписание вошедшего врача;
  • при создании пациента и оформлении приёма идентификатор врача брался из активной пользовательской сессии;
  • созданная медицинская запись сохранялась от имени вошедшего врача;
  • в журнале действий сохранялись сведения о пользователе, выполнившем операцию.

Учётная запись администратора создаётся без привязки к конкретному врачу или пациенту. После создания учётной записи пользователю передаются персональные данные для входа: логин и первоначальный пароль.

2.2. Вход и пользовательская сессия

Для начала работы необходимо:

  1. Открыть браузер.
  2. Ввести в адресную строку адрес приложения, предоставленный администратором или техническим специалистом.
  3. Дождаться загрузки страницы входа в «МИС Нефролога».
  4. Ввести персональный логин в поле «Логин».
  5. Ввести пароль в поле «Пароль».
  6. Нажать кнопку «Войти».

При вводе пароля символы скрываются. Перед отправкой формы рекомендуется убедиться, что выбрана правильная раскладка клавиатуры, не включена клавиша Caps Lock и в начале или конце логина отсутствуют лишние пробелы.

После нажатия кнопки «Войти» система проверяет наличие пользователя с указанным логином и соответствие введённого пароля сохранённым данным. Пароль не хранится в приложении в открытом виде: для проверки используется его защищённое представление.

Если логин и пароль введены правильно, создаётся пользовательская сессия и открывается главная страница. В верхней части внутренних страниц отображаются имя вошедшего пользователя, его роль и команда «Выйти». Эти сведения позволяют проверить, под какой учётной записью выполняется работа.

Если логин или пароль указаны неверно, система остаётся на странице входа и выводит сообщение: «Неверный логин или пароль».

В этом случае необходимо повторно проверить введённые данные. Система намеренно не сообщает отдельно, что именно введено неправильно: логин или пароль.

Если войти не удаётся после повторной проверки данных, необходимо обратиться к специалисту, ответственному за сопровождение приложения. При обращении следует сообщить используемый логин и текст отображаемого сообщения. Передавать свой пароль другим лицам не следует.

После успешного входа приложение создаёт защищённую пользовательскую сессию. В ней сохраняются только сведения, необходимые для определения пользователя и его прав доступа:

  • идентификатор пользователя;
  • логин;
  • отображаемое имя;
  • роль;
  • идентификатор врача, если вошёл пользователь с ролью «Врач»;
  • время входа и время последней активности.

Медицинские сведения пациента в пользовательской сессии не сохраняются.

Во время активной работы с формами приложение поддерживает сессию: учитываются нажатия клавиш, переходы между полями, щелчки мыши и изменение значений. Это снижает вероятность завершения сессии в процессе заполнения объёмной формы приёма.

Если пользователь в течение 40 минут не выполняет никаких действий, сессия завершается автоматически. При следующем обращении к системе выводится сообщение:

«Сессия истекла из-за бездействия. Войдите снова, чтобы продолжить работу».

После этого необходимо повторно ввести логин и пароль. Автоматическое завершение неактивной сессии используется для защиты медицинской информации, если пользователь оставил рабочее место, не выполнив выход из системы.

2.3. Роли и права доступа

В рабочей версии приложения предусмотрены две основные пользовательские роли:

  • врач;
  • администратор.

Роль определяет, какие разделы и операции доступны пользователю. Проверка прав выполняется при отображении пунктов меню и на сервере.

Роль «Врач» предназначена для непосредственного ведения медицинского приёма. Для роли «Врач» доступны:

  • главная страница со списком приёмов;
  • поиск и фильтрация приёмов;
  • список пациентов;
  • поиск пациента по персональным данным;
  • просмотр электронной медицинской карты пациента;
  • просмотр истории приёмов пациента;
  • просмотр сведений, сохранённых во время выбранного приёма;
  • просмотр результатов лабораторных и инструментальных исследований;
  • просмотр рассчитанных нефрологических показателей;
  • просмотр диагнозов, назначений и рекомендаций;
  • раздел расписания;
  • автоматическое открытие собственного расписания при переходе в раздел;
  • выбор рабочей недели;
  • просмотр запланированных посещений;
  • создание записи в расписании;
  • редактирование записи в расписании;
  • поиск существующего пациента при создании записи;
  • внесение предварительных данных нового пациента в расписание;
  • изменение статуса запланированного посещения;
  • указание причины отмены записи;
  • переход из расписания к оформлению приёма;
  • регистрация нового пациента с одновременным созданием первичного приёма;
  • оформление первичного приёма существующего пациента, записанного через расписание;
  • оформление повторного приёма;
  • внесение жалоб, анамнеза и данных объективного осмотра;
  • внесение лабораторных и инструментальных исследований;
  • выбор диагнозов по МКБ-10;
  • внесение лекарственных назначений, диеты и рекомендаций;
  • сохранение медицинской записи;
  • экспорт выбранного приёма в документ Microsoft Word;
  • использование горячих клавиш при заполнении формы и навигации.

При создании пациента или приёма врач определяется автоматически по активной учётной записи. Изменить врача через форму приёма невозможно. Такой порядок исключает случайное сохранение медицинской записи от имени другого специалиста.

Создание первичных и повторных приёмов доступно только пользователю с ролью «Врач», связанному с записью медицинского работника. Если учётная запись имеет роль врача, но не связана с записью в справочнике врачей, система не разрешит оформление приёма и сообщит о недостаточности прав или отсутствии необходимой привязки.

Роль «Администратор» предназначена для организационного контроля и работы с административными разделами приложения.

Администратору доступны:

  • главная страница со списком приёмов;
  • поиск и фильтрация приёмов;
  • список пациентов;
  • просмотр электронной медицинской карты пациента;
  • просмотр истории и содержания сохранённых приёмов;
  • просмотр медицинских данных и сформированных расчётных показателей;
  • экспорт выбранного приёма в документ Microsoft Word;
  • раздел расписания;
  • выбор врача, расписание которого необходимо открыть;
  • просмотр расписаний врачей;
  • создание и редактирование записей в расписании;
  • поиск пациента при работе с расписанием;
  • изменение статуса запланированного посещения;
  • указание причины отмены записи;
  • журнал аудита;
  • просмотр действий пользователей;
  • фильтрация событий журнала;
  • просмотр подробного протокола отдельного события;
  • просмотр протокола действий, связанных с конкретным приёмом;
  • выгрузка журнала аудита в формате CSV.

При первоначальном открытии расписания администратором конкретный врач не выбран, расписание отображается пустым. Для загрузки данных необходимо выбрать врача.

Администратор не связан с записью конкретного врача и не может создавать медицинские приёмы.

2.4. Завершение работы

После завершения работы необходимо выйти из системы. Для этого следует нажать ссылку «Выйти» в правой части верхней панели. После выхода активная сессия удаляется, и приложение возвращается на страницу входа. Для повторного доступа потребуется снова ввести логин и пароль.

Особенно важно выполнять выход:

  • при работе на общем компьютере;
  • перед передачей рабочего места другому сотруднику;
  • по окончании рабочего дня;
  • перед уходом от компьютера на продолжительное время;
  • при обнаружении, что в приложении выполнен вход под чужой учётной записью.

Закрытие вкладки браузера не завершит пользовательскую сессию.

Логин и пароль являются персональными. Не допускается передавать их другим сотрудникам или использовать одну учётную запись несколькими врачами. Все значимые действия в системе регистрируются с указанием вошедшего пользователя, поэтому работа под чужой учётной записью приводит к неправильному определению автора медицинской записи и искажению журнала действий.

3. Модуль «Список приёмов»

3.1. Назначение и фильтры

Модуль «Список приёмов» является главной рабочей страницей приложения. Он предназначен для просмотра зарегистрированных приёмов, поиска нужной медицинской записи и перехода в электронную медицинскую карту пациента.

При открытии страницы система загружает список приёмов из базы данных. По умолчанию отображаются все доступные приёмы, расположенные от новых к старым. Для каждого приёма выводятся сведения о пациенте, возрасте пациента на дату приёма, дате приёма, враче и месте оказания медицинской помощи.

Над списком расположен блок фильтров для поиска приёмов по филиалу, отделению, врачу, ФИО пациента или периоду. Несколько фильтров можно использовать одновременно.

Фильтр «Филиал» предназначен для отбора приёмов, проведённых в определённом филиале медицинской организации. По умолчанию установлено значение «Все филиалы». При этом ограничение по филиалу не применяется. После выбора филиала система обновляет связанные списки отделений и врачей. В списках остаются только отделения и врачи, относящиеся к выбранному филиалу. При изменении филиала ранее выбранные отделение и врач сбрасываются. После этого необходимо при необходимости выбрать их повторно.

Фильтр «Отделение» предназначен для отбора приёмов по конкретному месту приёма. При первоначальном открытии страницы поле недоступно и содержит подсказку «Сначала выберите филиал». Поле становится доступным после выбора филиала или врача. Список отделений формируется с учётом уже выбранных значений:

  • при выбранном филиале отображаются отделения этого филиала;
  • при выбранном враче отображаются отделения, в которых работает этот врач;
  • при одновременно выбранных филиале и враче отображаются отделения, соответствующие обоим условиям.

Значение «Все отделения» означает, что ограничение по отделению не применяется. Если для выбранной комбинации филиала и врача подходящие отделения отсутствуют, в поле отображается сообщение «Нет доступных отделений».

Фильтр «Врач» предназначен для отбора приёмов, проведённых определённым врачом. По умолчанию установлено значение «Все врачи». При этом в список включаются приёмы всех врачей.

Состав списка врачей зависит от выбранного филиала и отделения:

  • если филиал и отделение не выбраны, отображается полный список врачей;
  • если выбран филиал, отображаются врачи, работающие в этом филиале;
  • если выбрано отделение, отображаются врачи, связанные с этим отделением;
  • если выбраны филиал и отделение, отображаются врачи, соответствующие обоим условиям.

После выбора врача список отделений также обновляется. В нём остаются места приёма, связанные с выбранным врачом.

Поле «Поиск по ФИО» предназначено для поиска приёмов конкретного пациента.

Поиск выполняется отдельно по:

  • фамилии;
  • имени;
  • отчеству.

Можно вводить полное значение или его часть. Регистр букв не учитывается. Для выполнения поиска необязательно вводить ФИО полностью. Достаточно указать известную часть фамилии, имени или отчества. Если одновременно установлены другие фильтры, поиск по ФИО применяется совместно с ними.

Фильтр «Период» определяет временной интервал и порядок отображения приёмов. В поле доступны следующие значения:

«Все приёмы» — отображаются приёмы за весь период. По умолчанию новые приёмы располагаются выше старых.

«Сегодня» — отображаются приёмы с датой, совпадающей с текущей датой.

«Последние 7 дней» — отображаются приёмы за текущий день и семь предшествующих календарных дней.

«Последние 30 дней» — отображаются приёмы за текущий день и тридцать предшествующих календарных дней.

«Последний год» — отображаются приёмы за период от соответствующей даты предыдущего года до текущей даты.

«Сначала старые» — отображаются все найденные приёмы в порядке от более ранних к более поздним.

«Сначала новые» — отображаются все найденные приёмы в порядке от более поздних к более ранним.

При выборе периода он применяется совместно с фильтрами по филиалу, отделению, врачу и ФИО пациента.

3.2. Кнопки и состав списка

Кнопка «Применить фильтры» загружает список приёмов в соответствии с установленными значениями. Перед нажатием кнопки можно одновременно:

  • выбрать филиал;
  • выбрать отделение;
  • выбрать врача;
  • ввести ФИО или часть ФИО пациента;
  • выбрать период.

После нажатия кнопки таблица обновляется без перехода на другую страницу. Фильтры также можно применить нажатием клавиши Enter, если курсор находится в блоке фильтрации.

Кнопка «Сбросить» отменяет установленные условия отбора и возвращает фильтры в исходное состояние. После сброса:

  • выбирается значение «Все филиалы»;
  • выбирается значение «Все врачи»;
  • очищается поле поиска по ФИО;
  • выбирается значение «Все приёмы»;
  • очищается выбранное отделение;
  • поле отделения снова становится недоступным до выбора филиала или врача;
  • повторно загружается общий список приёмов.

После сброса приёмы отображаются от новых к старым.

Кнопка «Новый пациент» открывает форму первичного консультативного приёма нового пациента. На открывшейся странице вводятся персональные сведения пациента и данные первого приёма. После сохранения в системе одновременно создаются:

  • запись пациента;
  • электронная медицинская карта;
  • медицинская запись первичного приёма.

Кнопка используется только в том случае, если пациент ранее не был зарегистрирован в системе.

Результаты отображаются в таблице «Список приёмов». Каждая строка таблицы соответствует одному сохранённому приёму. Таблица содержит следующие столбцы:

«Пациент» — фамилия, имя и отчество пациента. Если отчество не указано, отображаются фамилия и имя.

«Возраст» — возраст пациента на дату выбранного приёма. Возраст выводится в полных годах.

«Дата приёма» — дата проведения приёма в формате день, месяц и год.

«Врач» — фамилия, имя и отчество врача, оформившего приём.

«Отделение» — наименование места, в котором проводился приём.

«Филиал» — наименование филиала, к которому относится место приёма.

«ЭМК» — кнопка перехода в электронную медицинскую карту пациента.

Если отдельное значение отсутствует, вместо него в таблице отображается прочерк.

В столбце «ЭМК» каждой строки находится кнопка открытия электронной медицинской карты. После нажатия кнопки открывается электронная медицинская карта пациента. В ней автоматически выбирается тот приём, из строки которого был выполнен переход. Это позволяет сразу просмотреть медицинскую запись нужной даты без дополнительного поиска в истории пациента.

3.3. Сортировка и служебные сообщения

В таблице предусмотрена сортировка по следующим столбцам:

  • «Пациент»;
  • «Возраст»;
  • «Дата приёма»;
  • «Врач».

Рядом с названиями этих столбцов отображаются стрелки вверх и вниз.

Стрелка вверх устанавливает сортировку по возрастанию:

  • ФИО пациента и врача — по алфавиту;
  • возраст — от меньшего к большему;
  • дата приёма — от более ранней к более поздней.

Стрелка вниз устанавливает сортировку по убыванию:

  • ФИО пациента и врача — в обратном алфавитном порядке;
  • возраст — от большего к меньшему;
  • дата приёма — от более поздней к более ранней.

Сортировку также можно изменить нажатием на название столбца. При повторных нажатиях направление переключается между возрастанием и убыванием. Активное направление обозначается выделенной стрелкой. Столбцы «Отделение», «Филиал» и «ЭМК» не сортируются.

Все условия отбора применяются одновременно. Например, можно выбрать:

  • определённый филиал;
  • отделение этого филиала;
  • конкретного врача;
  • период «Последние 30 дней»;
  • часть фамилии пациента.

В результате будут показаны только приёмы, соответствующие всем указанным условиям. Если приёмы не соответствуют хотя бы одному из выбранных условий, они не включаются в список. Для расширения результатов необходимо очистить часть фильтров или нажать кнопку «Сбросить».

Во время получения информации в таблице отображается сообщение «Загрузка данных...».

Если приёмы, соответствующие установленным условиям, отсутствуют, отображается сообщение «Нет записей».

Сообщение «Нет записей» означает, что в базе данных не найдено приёмов, одновременно соответствующих всем выбранным фильтрам. Для повторного поиска следует изменить условия отбора или сбросить фильтры.

Если данные не удалось получить из-за технической ошибки, отображается сообщение «Ошибка загрузки данных». В этом случае следует обновить страницу. Если сообщение появляется повторно, необходимо сообщить разработчику адрес страницы, установленный набор фильтров и время возникновения ошибки.

4. Модуль «Электронная медицинская карта»

4.1. Назначение и переход в ЭМК

Электронная медицинская карта предназначена для просмотра уже сохранённых медицинских записей. Поля выбранного приёма на этой странице не редактируются. Для внесения новых сведений создаётся новый приём с помощью кнопки «Добавить приём». Каждая новая медицинская запись сохраняется отдельно. Ранее оформленные приёмы остаются в истории пациента.

В электронной медицинской карте доступны следующие действия:

  • просмотреть основные сведения о пациенте (ФИО, дату рождения, номер телефона);
  • ознакомиться с полной историей приёмов;
  • выбрать приём за определённую дату;
  • просмотреть жалобы и анамнез;
  • просмотреть результаты объективного исследования;
  • оценить динамику лабораторных и инструментальных показателей;
  • просмотреть автоматически рассчитанные нефрологические показатели;
  • ознакомиться с прогнозом по KDIGO;
  • просмотреть диагнозы, назначения и рекомендации;
  • перейти к оформлению нового приёма;
  • скачать консультативное заключение по любому приему в формате Microsoft Word.

Сведения в электронной медицинской карте сгруппированы по приёмам. Каждый приём представляет собой отдельную медицинскую запись, связанную с пациентом, врачом, датой и местом оказания медицинской помощи.

Открыть электронную медицинскую карту можно из списка приёмов или через модуль расписания, если пациент записан на прием.

В списке приёмов необходимо найти нужную строку и нажать кнопку в столбце «ЭМК». После перехода в электронной медицинской карте будет сразу выбран тот приём, из строки которого она была открыта.

При переходе из расписания для оформления и сохранения нового приёма также может быть открыта электронная медицинская карта в новой вкладке.

Если в адресе страницы не указан конкретный приём, система автоматически выбирает последний приём пациента.

4.2. Структура и история приёмов

Страница состоит из трёх основных частей:

  • заголовок с фамилией, именем и отчеством пациента;
  • левая панель «История приёмов»;
  • область просмотра выбранного приёма.

Панель «История приёмов» содержит все сохранённые приёмы пациента. Для каждого приёма отображаются: дата приёма и ФИО врача, оформившего медицинскую запись. Приёмы расположены от новых к старым. Последний приём находится в верхней части списка. Текущий выбранный приём выделяется цветом. Для просмотра другой медицинской записи необходимо нажать на соответствующую дату.

После выбора приёма правая часть страницы обновляется. В ней отображаются сведения, относящиеся к выбранной дате, а также результаты исследований пациента, зарегистрированные не позднее этой даты. Если у пациента отсутствуют сохранённые приёмы, в панели отображается сообщение «Нет приёмов».

В нижней части панели «История приёмов» расположена кнопка «Добавить приём». Кнопка открывает форму нового приёма уже зарегистрированного пациента. Повторно вводить фамилию, имя, отчество, дату рождения, пол и номер телефона пациента не требуется.

При создании нового приёма приложение использует сведения последней медицинской записи для предварительного заполнения части полей. Данные актуализируются с учётом состояния пациента на текущую дату, после чего сохраняется новая медицинская запись. После сохранения новый приём добавляется в историю электронной медицинской карты и располагается в верхней части списка.

В заголовке выбранной медицинской записи (область просмотра деталей приема) указывается вид приёма:

  • «Консультативный приём (первичный)»;
  • «Консультативный приём (повторный)».

Первичным считается самый ранний сохранённый приём пациента в данной медицинской организации. Все последующие приёмы отображаются как повторные. Определение вида приёма выполняется автоматически на основании истории обращений пациента.

В начале медицинской записи отображаются:

  • дата и время приёма;
  • место приёма (полное наименование медицинской организации, включая адрес отделения);
  • ФИО врача.

Далее выводятся краткие сведения о пациенте:

  • дата рождения;
  • возраст на дату выбранного приёма;
  • пол;
  • номер телефона.

Возраст отображается на дату конкретного приёма. При просмотре приёмов за разные годы значение возраста может отличаться.

Поля, которые не заполнялись во время приёма, в разделе не отображаются.

Раздел «Опрос» содержит сведения, собранные врачом во время выбранного приёма:

  • анамнез жизни;
  • анамнез заболевания;
  • жалобы;
  • наследственность;
  • сопутствующие заболевания.

Анамнез жизни включает сведения, внесённые в соответствующие подразделы формы приёма: образование и профессиональный маршрут, жилищные условия, перенесённые заболевания, привычные интоксикации, гинекологический анамнез, семейную жизнь, аллергологический, эпидемиологический и экспертно-трудовой анамнез.

Анамнез заболевания формируется из сведений о начале и течении текущего заболевания.

В разделе «Данные объективного исследования больного» отображаются результаты объективного исследования, сохранённые во время выбранного приёма:

  • общее состояние (отображается как удовлетворительное, средней тяжести или тяжёлое);
  • состояние сознания (отображается как ясное, спутанное, сопорозное или коматозное);
  • положение в постели (отображается как активное, пассивное или вынужденное);
  • особенности положения в постели;
  • телосложение;
  • рост, см;
  • массу тела, кг;
  • индекс массы тела, кг/м² (рассчитывается автоматически);
  • тип конституции;
  • состояние кожи и слизистых оболочек;
  • локализацию отёков;
  • состояние лимфатических узлов;
  • состояние щитовидной железы;
  • состояние опорно-двигательного аппарата;
  • температуру тела, °C;
  • артериальное давление, мм.рт.ст.;
  • комментарий к артериальному давлению;
  • частоту сердечных сокращений, уд/мин;
  • состояние вен;
  • результаты аускультации лёгких;
  • состояние живота;
  • результаты пальпации почек;
  • дополнительные сведения о пальпации почек;
  • результат симптома Пастернацкого (отображается как положительный или отрицательный с указанием стороны: справа, слева или с двух сторон).

4.3. Исследования, расчёты и заключение

Лабораторные, инструментальные и расчётные показатели представлены в виде динамических таблиц.

В таблицах:

  • наименования показателей располагаются по строкам;
  • даты исследований располагаются по столбцам;
  • на пересечении показателя и даты отображается сохранённое значение.

Такое представление позволяет сопоставлять результаты за разные даты и оценивать их динамику.

При просмотре выбранного приёма отображаются исследования, выполненные на дату этого приёма или ранее. Результаты, зарегистрированные после выбранного приёма, в его исторические таблицы не включаются.

Для просмотра более поздних исследований необходимо выбрать более поздний приём в панели «История приёмов».

Таблица общего анализа крови содержит следующие показатели:

  • гемоглобин, г/л;
  • эритроциты, ×10¹²/л;
  • лейкоциты, ×10⁹/л;
  • тромбоциты, ×10⁹/л;
  • скорость оседания эритроцитов, мм/ч;
  • средний объём эритроцита MCV, фл;
  • гематокрит, %.

Если общий анализ крови не вносился, отображается сообщение «Общий анализ крови не предоставлен».

Таблица биохимического анализа крови содержит:

  • креатинин, мкмоль/л;
  • мочевину, ммоль/л;
  • мочевую кислоту, мкмоль/л;
  • глюкозу, ммоль/л;
  • общий белок, г/л;
  • альбумин, г/л;
  • калий, ммоль/л;
  • кальций, ммоль/л;
  • фосфор, ммоль/л;
  • ферритин, нг/мл;
  • паратиреоидный гормон, пг/мл.

Если биохимический анализ крови не вносился, отображается сообщение «Биохимический анализ крови не предоставлен».

В разделе отображаются автоматически рассчитанные показатели функции почек:

  • скорость клубочковой фильтрации по формуле CKD-EPI 2021, мл/мин/1,73 м²;
  • скорость клубочковой фильтрации по формуле Кокрофта — Голта, мл/мин;
  • стадия хронической болезни почек (определяется по скорости клубочковой фильтрации, рассчитанной по формуле CKD-EPI 2021, и отображается в виде: С1; С2; С3а; С3б; С4; С5).

Расчётные значения формируются приложением на основании сведений, внесённых во время приёма. В электронной медицинской карте они доступны только для просмотра и не изменяются вручную. Если необходимые исходные данные отсутствовали, соответствующий расчётный показатель не отображается.

Таблица общего анализа мочи содержит:

  • удельный вес;
  • белок, г/л;
  • лейкоциты;
  • эритроциты;
  • бактерии.

Если общий анализ мочи не вносился, отображается сообщение «Общий анализ мочи не предоставлен».

В разделе «Альбуминурия по KDIGO» отображаются:

  • альбумин мочи;
  • единица измерения альбумина мочи (мг/л или г/л);
  • креатинин мочи;
  • единица измерения креатинина мочи (ммоль/л или мкмоль/л);
  • отношение альбумина к креатинину мочи, мг/ммоль (рассчитывается автоматически);
  • категория альбуминурии (отображается как А1, А2 или А3).

Если сведения отсутствуют, отображается сообщение «Данные об альбуминурии не предоставлены».

Таблица ультразвукового исследования почек содержит:

  • размер левой почки;
  • толщину паренхимы левой почки, мм;
  • размер правой почки;
  • толщину паренхимы правой почки, мм;
  • описание исследования.

Если результаты ультразвукового исследования не вносились, отображается сообщение «УЗИ почек не предоставлено».

Матрица риска по KDIGO предназначена для просмотра сохранённых оценок риска прогрессирования хронической болезни почек. Строки матрицы соответствуют результатам оценки скорости клубочковой фильтрации (стадии ХБП). Для каждой строки указываются: дата исследования и стадия ХБП. Столбцы матрицы соответствуют результатам исследования альбуминурии. Для каждого столбца указываются: дата исследования и категория альбуминурии.

На пересечении строки и столбца отображается уровень риска, рассчитанный для соответствующего сочетания стадии ХБП и категории альбуминурии. Уровень риска дополнительно обозначается цветом.

В матрице отображаются только сохранённые и корректно рассчитанные оценки. Комбинации, для которых оценка не выполнялась, обозначаются прочерком. Если сохранённые оценки отсутствуют, отображается сообщение «Сохранённые оценки риска по KDIGO отсутствуют».

В разделе «Заключение» отображается текстовое описание определенного прогноза по KDIGO с указанием дат анализов, на основе которых были рассчитаны СКФ и альбуминурия. Если во время выбранного приёма было сформировано несколько оценок, каждая сохранённая оценка отображается отдельной строкой. Если для расчёта недостаточно данных, отображается сообщение: «Невозможно оценить риск прогрессирования ХБП и развития ХПН, данные по альбуминурии и СКФ не предоставлены».

В электронной медицинской карте диагнозы по МКБ-10 отображаются по категориям: основной диагноз; осложнения основного диагноза; сопутствующие заболевания. К каждому диагнозу может быть сохранено текстовое дополнение под соответствующей записью.

Далее в заключении указаны:

  • диета;
  • рекомендации;
  • медикаментозная терапия;
  • дата следующего контроля.

Для каждого лекарственного препарата отображается наименование лекарственного препарата по МНН, дозировка, схема приёма. Если назначено несколько препаратов, они выводятся отдельными строками. Дата следующего контроля отображается в формате день, месяц и год.

4.4. Скачивание заключения

В нижней части выбранного приёма расположена кнопка «Скачать заключение». После нажатия кнопки приложение формирует консультативное заключение в формате DOCX и сохраняет его на компьютер пользователя. Экспортируется выбранный приём, а не вся электронная медицинская карта.

Документ содержит всю информацию, сохраненную в данном приеме:

  • сведения о медицинской организации и месте приёма;
  • заголовок с указанием типа приема;
  • ФИО пациента, дату рождения, возраст на момент приёма;
  • жалобы, анамнез и основные данные осмотра;
  • результаты лабораторных и инструментальных исследований за последние 3 приема;
  • заключение;
  • дату приёма и ФИО врача.

Имя файла формируется автоматически по шаблону: «Заключение_ФИО пациента_дата приёма.docx». Сформированный документ можно открыть в Microsoft Word или другой программе, поддерживающей формат DOCX, сохранить в выбранную папку и распечатать.

5. Модуль «Форма добавления приёма»

5.1. Назначение и открытие формы

Форма приёма предназначена для регистрации нового пациента и оформления медицинской записи по результатам консультации врача-нефролога.

В приложении используются два варианта формы:

  • первичный консультативный приём;
  • повторный консультативный приём.

В форме предусмотрен ввод сведений о пациенте, жалоб, анамнеза, результатов объективного осмотра, лабораторных и инструментальных исследований и заключения.

При вводе клинических данных приложение автоматически рассчитывает индекс массы тела, скорость клубочковой фильтрации, стадию ХБП, отношение альбумина к креатинину мочи, категорию альбуминурии и прогноз по KDIGO.

После сохранения приёма создаётся новая медицинская запись, которая становится доступна в электронной медицинской карте пациента.

Для создания первичного приема необходимо:

  1. Открыть модуль «Список приёмов».
  2. Нажать кнопку «Создать первичный прием».
  3. Заполнить сведения о пациенте.
  4. Заполнить данные первого приёма.
  5. Нажать кнопку «Сохранить прием».

После сохранения система одновременно создаёт:

  • запись пациента;
  • электронную медицинскую карту;
  • медицинскую запись первого приёма.

Форму первичного приёма также можно открыть из расписания, если пациент был предварительно записан на прием. При этом ФИО, дата рождения, пол, номер телефона, место, дата и время приёма подставляются в форму автоматически.

Для создания повторного приёма необходимо:

  1. Открыть электронную медицинскую карту пациента.
  2. Нажать кнопку «Добавить приём» в левой панели «История приёмов».

После перехода открывается форма нового приёма выбранного пациента.

Форму повторного приема также можно открыть из расписания при переходе к оформлению запланированного посещения. При этом ФИО, дата рождения, пол, номер телефона, место, дата и время приёма подставляются в форму автоматически.

При оформлении повторного приёма в левой части страницы отображается панель «История приёмов». В панели для каждого приёма указаны: дата приёма; ФИО врача. Для просмотра предыдущей медицинской записи необходимо нажать на соответствующую дату. Выбранный приём откроется в новой вкладке браузера. Форма, заполняемая в основной вкладке, при этом остаётся открытой. Внесённые в неё данные не заменяются данными просматриваемого приёма. После просмотра предыдущей записи необходимо вернуться на вкладку с формой нового приёма.

При открытии формы повторного приёма приложение загружает часть сведений из его последней медицинской записи. Под заголовком отображается сообщение: «В форму подгружены данные последнего приёма». В сообщении также указывается дата последнего приёма.

Автоматически подставленные значения выделяются светло-жёлтым цветом. Значение можно оставить без изменений, дополнить, заменить или удалить. После изменения поля жёлтая подсветка снимается.

В форму могут подставляться сведения из следующих разделов:

  • жалобы;
  • анамнез жизни;
  • анамнез заболевания;
  • объективное исследование;
  • основной диагноз;
  • осложнения основного диагноза;
  • сопутствующие заболевания;
  • диета;
  • рекомендации;
  • медикаментозная терапия.

Результаты предыдущих лабораторных и инструментальных исследований отображаются динамических таблицах.

Дата следующего контроля из прошлого приёма не переносится. Для текущего приёма указывается новая дата.

5.2. Данные приёма и объективное исследование

При создании первичного приёма для пациента, не записанного на прием, обязательны к заполнению следующие поля: «Фамилия», «Имя», «Отчество», «Номер телефона», «Дата рождения», «Пол». Поле «Возраст» рассчитывается автоматически по дате рождения на дату приёма.

В блоке «Данные первого приёма» или «Данные нового приёма» отображаются основные сведения о консультации.

Поле «Врач» заполняется автоматически на основании учётной записи пользователя. Поле доступно только для просмотра. Выбрать другого врача в форме нельзя.

В поле «Место приёма» необходимо выбрать отделение или другое место работы врача. В списке отображаются только места приёма, связанные с вошедшим врачом.

В полях «Дата приёма» и «Время приёма» указываются дата и время консультации.

При открытии формы из списка приемов или из электронноц медицинской карты пациента подставляются текущие дата и время. При открытии формы из расписания подставляются дата, время и место запланированной записи.

При необходимости дату и время можно изменить до сохранения приёма.

Поле «Жалобы» является текстовым и ожидает на вход любые символы.

Раздел «Анамнез жизни» содержит многострочные поля:

  • «Образование и профессиональный анамнез»;
  • «Жилищные условия»;
  • «Перенесённые заболевания»;
  • «Привычные интоксикации»;
  • «Гинекологический анамнез»;
  • «Наследственность»;
  • «Семейная жизнь»;
  • «Аллергологический анамнез»;
  • «Эпидемиологический анамнез»;
  • «Страховой анамнез».

Для заполнения необходимо нажать на соответствующее поле и ввести текст.

Раздел «Анамнез данного заболевания» содержит два поля. «Начало болезни» — сведения о времени и обстоятельствах появления заболевания или первых симптомов. «Течение заболевания» — сведения о дальнейшем развитии заболевания, обследованиях, лечении и изменении состояния пациента. Оба поля являются многострочными.

Раздел «Данные объективного исследования больного» предназначен для внесения результатов осмотра пациента.

Для заполнения поля «Общее состояние» необходимо выбрать из выпадающего списка:

  • «Удовлетворительное»;
  • «Средней тяжести»;
  • «Тяжёлое».

Для заполнения поля «Сознание» необходимо выбрать из выпадающего списка:

  • «Ясное»;
  • «Спутанное»;
  • «Сопорозное»;
  • «Коматозное».

Для заполнения поля «Положение в постели» необходимо выбрать из выпадающего списка:

  • «Активное»;
  • «Пассивное»;
  • «Вынужденное».

«Особенности вынужденного положения» можно указать в дополнительном текстовом поле.

В поле «Телосложение» вводится текстовое описание.

В полях «Рост» и «Вес» указываются рост пациента в сантиметрах и масса тела в килограммах.

После ввода роста и веса приложение автоматически заполняет поле «ИМТ». Изменить рассчитанное значение вручную нельзя.

В поле «Тип конституции» необходимо выбрать из выпадающего списка:

  • «Нормостеник»;
  • «Астеник»;
  • «Гиперстеник».

В поле «Кожа и слизистые оболочки» вводится текстовое описание состояния кожи и видимых слизистых оболочек.

Блок «Отёки» разделён на периферические отёки и серозиты.

В подразделе «Периферические отёки» можно установить один или несколько флажков:

  • «Нет»;
  • «Нижние конечности»;
  • «Лицо/веки»;
  • «Верхние конечности».

Дополнительную локализацию или характеристику периферических отёков можно внести в поле «Комментарий».

В подразделе «Серозиты» можно установить один или несколько флажков:

  • «Нет»;
  • «Гидроторакс»;
  • «Гидроперикард»;
  • «Асцит».

Дополнительные сведения о серозитах можно внести в расположенное ниже поле «Комментарий».

Другие сведения об отёчном синдроме вводятся в поле «Дополнительно».

При повторном приёме над блоком отображается описание отёков из последней медицинской записи. Флажки для текущего приёма устанавливаются заново.

В следующих полях можно указать:

  • состояние лимфатических узлов;
  • состояние щитовидной железы;
  • состояние опорно-двигательного аппарата;
  • температуру тела;
  • систолическое артериальное давление;
  • диастолическое артериальное давление;
  • примечание к артериальному давлению;
  • частоту сердечных сокращений;
  • состояние вен;
  • результаты аускультации лёгких;
  • состояние живота.

Температура тела, артериальное давление и частота сердечных сокращений вводятся в соответствующие числовые поля, на которые наложены ограничения во избежания нереальных значений и опечаток. В поле «Примечание к АД» можно указать положение пациента, руку, особенности измерения или другие сведения.

В поле «Пальпация почек» необходимо выбрать из выпадающего списка:

  • «Пальпируются»;
  • «Не пальпируются».

Дополнительное описание вносится в поле «Уточнение».

В поле «Симптом Пастернацкого» необходимо выбрать из выпадающего списка:

  • «Положительный»;
  • «Отрицательный».

После выбора результата необходимо выбрать из выпадающего списка:

  • «Справа»;
  • «Слева»;
  • «С двух сторон».

Если результат симптома выбран, а сторона не указана, приложение выделяет поле и выводит сообщение: «Укажите сторону симптома Пастернацкого». При изменении результата ранее выбранная сторона очищается, после чего её необходимо выбрать заново.

5.3. Лабораторные и инструментальные исследования

Форма содержит следующие структурированные блоки для добавления результатов лабораторных и инструментальных исследований:

  • общий анализ крови;
  • общий анализ мочи;
  • биохимический анализ крови;
  • расчётные показатели;
  • альбуминурия по KDIGO;
  • другие лабораторные исследования;
  • УЗИ почек;
  • другие инструментальные исследования.

Способ внесения результатов отличается для первичного и повторного приёма.

При первичном приёме каждый анализ представлен отдельным блоком с полями ввода. Для внесения дополнительного результата необходимо нажать соответствующую кнопку, например, «Добавить ещё ОАК». На странице появится новый блок с отдельной датой исследования и отдельными полями показателей. Дополнительный блок можно удалить кнопкой «Удалить анализ».

При повторном приёме предыдущие результаты отображаются в динамических таблицах. Для добавления нового исследования следует нажать кнопку над соответствующей таблицей. После нажатия справа появляется новый выделенный столбец с датой и полями ввода, страница автоматически прокручивается к нему, а курсор устанавливается в поле даты исследования. Кнопку добавления можно нажимать несколько раз, если в рамках одного приёма требуется зарегистрировать несколько анализов одного типа за разные даты.

Все поля лабораторных показателей являются необязательными. Если показатель не исследовался или результат отсутствует, поле можно оставить пустым.

Для числовых показателей можно использовать целые и дробные значения. В качестве десятичного разделителя допускаются запятая и точка. Пробелы внутри числа удаляются автоматически.

Для каждого анализа указывается дата исследования (не может быть позже даты оформляемого приёма).

Указанные ниже диапазоны определяют значения, которые приложение допускает к сохранению. Границы диапазонов включаются. Эти диапазоны не являются референсными интервалами лабораторной нормы, а нужны лишь для устранения опечаток и сохранения нереалистичных значений.

В блоке общего анализа крови предусмотрены поля для ввода:

  • дата исследования — корректная календарная дата, не позднее даты приёма;
  • гемоглобин, г/л — допустимое значение от 20 до 250;
  • эритроциты, ×10¹²/л — допустимое значение от 0,5 до 10;
  • лейкоциты, ×10⁹/л — допустимое значение от 0,1 до 300;
  • тромбоциты, ×10⁹/л — допустимое значение от 5 до 1500;
  • СОЭ, мм/ч — допустимое значение от 0 до 150;
  • средний объём эритроцита MCV, фл — допустимое значение от 40 до 140;
  • гематокрит, % — допустимое значение от 5 до 70. Можно вводить в процентах и в виде доли.

В блоке общего анализа мочи предусмотрены поля для ввода:

  • дата исследования — корректная календарная дата, не позднее даты приёма;
  • удельный вес мочи — допустимое значение от 1,000 до 1,050 (1000-1050);
  • белок, г/л — допустимое значение от 0 до 20;
  • лейкоциты — допустимое числовое значение от 0 до 10 000;
  • эритроциты — допустимое числовое значение от 0 до 10 000;
  • бактерии — допустимое числовое значение от 0 до 100.

Для полей «Лейкоциты», «Эритроциты» и «Бактерии» в форме не установлена отдельная единица измерения. Значения вносятся в том числовом представлении, в котором они указаны в результате исследования.

В блоке биохимического анализа крови предусмотрены поля для ввода:

  • дата исследования — корректная календарная дата, не позднее даты приёма;
  • креатинин, мкмоль/л — допустимое значение от 15 до 3000;
  • мочевина, ммоль/л — допустимое значение от 0,5 до 80;
  • мочевая кислота, мкмоль/л — допустимое значение от 50 до 1500;
  • глюкоза, ммоль/л — допустимое значение от 0,5 до 40;
  • общий белок, г/л — допустимое значение от 20 до 120;
  • альбумин, г/л — допустимое значение от 10 до 70;
  • калий, ммоль/л — допустимое значение от 1 до 10;
  • кальций, ммоль/л — допустимое значение от 1 до 4;
  • фосфор, ммоль/л — допустимое значение от 0,2 до 5;
  • ферритин, нг/мл — допустимое значение от 0 до 10 000;
  • паратиреоидный гормон (ПТГ), пг/мл — допустимое значение от 0 до 10 000.

После ввода значения креатинина приложение автоматически рассчитывает и отображает в самостоятельной таблице:

  • скорость клубочковой фильтрации по формуле CKD-EPI 2021, мл/мин/1,73 м²;
  • скорость клубочковой фильтрации по формуле Кокрофта-Голта, мл/мин;
  • стадию ХБП по KDIGO.

Стадия ХБП по СКФ определяется следующим образом:

  • С1 — СКФ 90 мл/мин/1,73 м² и выше;
  • С2 — СКФ от 60 до 89 мл/мин/1,73 м²;
  • С3а — СКФ от 45 до 59 мл/мин/1,73 м²;
  • С3б — СКФ от 30 до 44 мл/мин/1,73 м²;
  • С4 — СКФ от 15 до 29 мл/мин/1,73 м²;
  • С5 — СКФ менее 15 мл/мин/1,73 м².

Если в форму внесено несколько биохимических анализов, расчёт выполняется отдельно для каждого анализа. Рассчитанные значения отображаются в отдельных полях или в таблице расчётных показателей. Эти поля недоступны для ручного ввода и изменения.

В блоке альбуминурии предусмотрены поля для ввода:

  • дата исследования — корректная календарная дата, не позднее даты оформляемого приёма;
  • альбумин мочи — допустимое значение от 0 до 100 000;
  • единица измерения альбумина мочи — «мг/л» или «г/л»;
  • креатинин мочи — допустимое значение от 0,000001 до 1 000 000;
  • единица измерения креатинина мочи — «ммоль/л» или «мкмоль/л»;
  • экскреция альбумина суточная, мг/сут — допустимое значение от 0 до 1 000 000.

В блоке также отображаются расчётные поля:

  • ACR, мг/ммоль;
  • категория альбуминурии A1–A3;
  • источник, по которому определена категория.

Поля ACR и категории альбуминурии заполняются автоматически и недоступны для ручного изменения.

Для расчёта ACR необходимо указать:

  • альбумин мочи;
  • единицу измерения альбумина мочи;
  • креатинин мочи;
  • единицу измерения креатинина мочи.

Приложение автоматически приводит введённые значения к единым единицам измерения. Альбумин, указанный в г/л, переводится в мг/л. Креатинин, указанный в мкмоль/л, переводится в ммоль/л.

ACR рассчитывается как отношение альбумина мочи в мг/л к креатинину мочи в ммоль/л. Результат отображается в мг/ммоль с округлением до двух знаков после запятой.

Категория альбуминурии по ACR определяется следующим образом:

  • A1 — ACR менее 3 мг/ммоль;
  • A2 — ACR от 3 до 30 мг/ммоль включительно;
  • A3 — ACR более 30 мг/ммоль.

Под полем категории отображается пояснение, например:

«Категория рассчитана по ACR: 12,50 мг/ммоль».

Вместо альбумина и креатинина мочи можно указать значение в поле «Экскреция альбумина суточная, мг/сут». В этом случае ACR не рассчитывается, а категория определяется по суточной экскреции альбумина:

  • A1 — менее 30 мг/сут;
  • A2 — от 30 до 300 мг/сут включительно;
  • A3 — более 300 мг/сут.

Под полем категории отображается пояснение, например: «Категория рассчитана по суточной экскреции альбумина: 120 мг/сут». Если одновременно указаны альбумин мочи, креатинин мочи и суточная экскреция альбумина, категория рассчитывается по ACR. Суточная экскреция в этом случае сохраняется в медицинской записи, но не используется для определения категории.

Если заполнен только альбумин мочи или только креатинин мочи, ACR не рассчитывается. Частичное заполнение этих полей не препятствует сохранению приёма. Если при частично заполненных данных ACR указана суточная экскреция альбумина, категория определяется по суточной экскреции. Если отсутствуют как полный набор данных для расчёта ACR, так и суточная экскреция альбумина, поля ACR и категории остаются пустыми.

Поле «Другие лабораторные исследования» предназначено для внесения результатов, для которых в форме не предусмотрены отдельные структурированные поля. Информация вводится в свободной текстовой форме. Ограничения числовых значений для этого поля не применяются.

При оформлении нового приёма зарегистрированного пациента над полем отображается содержание этого раздела из последней медицинской записи. Предыдущий текст используется для просмотра и автоматически не копируется в текущий приём.

5.4. Заключение, диагнозы и назначения

В разделе «Заключение» находится блок «Оценка риска по KDIGO».

Текущий прогноз пересчитывается автоматически на основании стадии ХБП и категории альбуминурии, полученных из данных заполняемого приёма. До внесения необходимых показателей в блоке отображается сообщение о невозможности выполнить оценку. После расчёта приложение показывает один или несколько вариантов прогноза. Рядом с каждым вариантом расположен круглый переключатель. Необходимо выбрать круглый переключатель рядом с вариантом, который должен быть сохранён в медицинской записи. Выбранный вариант будет включён в результаты текущего приёма.

При повторном приёме доступна кнопка «Посмотреть историю прогнозов по KDIGO». После нажатия открывается история ранее сохранённых оценок. Она позволяет сопоставить категории СКФ и альбуминурии за разные даты. Повторное нажатие скрывает историю.

Поля «Основной диагноз по МКБ-10», «Осложнения основного диагноза по МКБ-10», «Сопутствующие заболевания по МКБ-10» связаны со справочником диагнозов.

Для поиска диагноза необходимо:

  1. Нажать на поле «Основной диагноз по МКБ-10» / «Осложнения основного диагноза по МКБ-10» / «Сопутствующие заболевания по МКБ-10».
  2. Начать вводить код МКБ-10, полное наименование, часть наименования или принятую медицинскую аббревиатуру: «ХБП» — хроническая болезнь почек; «ОПП» — острое повреждение почек; «ХПН» — почечная недостаточность; «СД» — сахарный диабет; «АГ» — артериальная гипертензия; «МКН» — минерально-костные нарушения; «МКБ» — мочекаменная болезнь.
  3. Выбрать нужный диагноз из списка подсказок.

Поиск не зависит от регистра букв и учитывает распространённые нефрологические сокращения. Дополнительную клиническую формулировку можно внести в поле «Уточнение по основному диагнозу».

После расчёта текущей категории СКФ приложение автоматически подставляет соответствующий диагноз хронической болезни почек в поле «Осложнения основного диагноза по МКБ-10». После ручного изменения выбранное значение сохраняется и не заменяется при последующем пересчёте СКФ в текущей форме. Автоматически подставленный диагноз можно изменить.

Один диагноз нельзя сохранить в текущем приёме несколько раз. Проверка выполняется одновременно для всех полей. Диагноз считается повторяющимся, если в двух полях указан одинаковый код МКБ-10 или одинаковое наименование. При обнаружении повторения оба поля выделяются, и рядом с ними отображается сообщение: «Этот диагноз уже указан в текущем приёме». Пока повторяющийся диагноз не удалён или не заменён, форма приёма не сохраняется.

Для устранения повторения необходимо:

  • удалить лишнюю строку;
  • очистить одно из полей;
  • выбрать другой диагноз;
  • перенести дополнительную информацию в поле уточнения уже выбранного диагноза.

После исправления сообщение исчезает, и форму можно сохранить.

Поля «Диета» и «Рекомендации» предназначены для ввода свободного текста. При повторном приёме в оба поля подставляются сведения из последней медицинской записи. Сведения можно актуализировать перед сохранением текущего приёма.

Блок «Медикаментозная терапия» содержит отдельную строку для каждого препарата с полями: название препарата; дозировка; режим приёма. При вводе названия препарата приложение показывает варианты из справочника. Подходящий вариант можно выбрать из выпадающего списка. Для добавления нового препарата необходимо нажать кнопку «Добавить ещё лекарство». После нажатия появляется новая пустая строка. Для удаления препарата необходимо нажать кнопку с символом «×» справа от соответствующей строки.

При повторном приёме лекарственные назначения из последней медицинской записи подставляются в форму. Дозировку и режим можно изменить, отменённый препарат — удалить, новый — добавить.

В поле «Дата следующего контроля» указывается планируемая дата следующего посещения или контрольного обследования. Дата выбирается из календаря. Она не может быть раньше: даты текущего приёма; текущей календарной даты. Дата следующего контроля из предыдущей медицинской записи автоматически не подставляется.

5.5. Навигация, проверка и сохранение

Форму приёма можно заполнять с помощью мыши и клавиатуры. Для стандартного последовательного перехода между доступными элементами формы используется клавиша Tab.

В правом нижнем углу страницы расположена кнопка «Горячие клавиши». После нажатия открывается окно со списком сочетаний клавиш, доступных в форме приёма. Закрыть окно можно кнопкой «Понятно», кнопкой закрытия в правом верхнем углу или клавишей Esc.

Для перехода между обычными полями формы используются сочетания:

  • Ctrl + стрелка вправо — перейти к следующему полю;
  • Ctrl + стрелка влево — перейти к предыдущему полю.

Эти сочетания действуют в полях, расположенных вне таблиц лабораторных и инструментальных исследований. При переходе приложение пропускает:

  • скрытые элементы;
  • заблокированные поля;
  • расчётные поля, недоступные для изменения;
  • элементы, которые в данный момент не отображаются.

После перехода выбранное поле прокручивается к центру экрана и получает фокус ввода.

Если фокус находится в первом или последнем доступном поле, приложение выводит сообщение:

  • «Это первое поле формы»;
  • «Это последнее поле формы».

В форме повторного приёма результаты лабораторных и инструментальных исследований отображаются в таблицах. Каждый новый результат добавляется отдельным столбцом.

Если курсор установлен в поле внутри таблицы, используются следующие клавиши:

  • стрелка вниз — перейти к следующему доступному полю в том же столбце;
  • стрелка вверх — перейти к предыдущему доступному полю в том же столбце;
  • Enter — перейти к следующему разделу формы;
  • Shift + Enter — перейти к предыдущему разделу формы.

При переходе стрелками приложение сохраняет текущий столбец. Например, из поля креатинина нового биохимического анализа стрелка вниз переводит курсор в следующее доступное поле этого же анализа. Строки таблицы, в которых отсутствуют поля ввода, пропускаются.

Если выше или ниже в текущем столбце больше нет доступных полей, отображается сообщение: «Выше в этом столбце полей нет»; «Ниже в этом столбце полей нет».

Сочетания Ctrl + стрелка влево и Ctrl + стрелка вправо внутри таблиц не применяются.

Для прокрутки длинной формы используются сочетания:

  • Ctrl + стрелка вниз — прокрутить страницу вниз;
  • Ctrl + стрелка вверх — прокрутить страницу вверх.

Прокрутка выполняется плавно небольшими участками. Сочетания работают независимо от текущего раздела формы.

Для быстрого перехода к списку приёмов используется сочетание Alt + M.

В форме повторного приёма сочетание Alt + P открывает электронную медицинскую карту этого пациента. Если после открытия формы было изменено хотя бы одно поле, перед переходом с помощью Alt + M или Alt + P появляется предупреждение: «В приёме есть несохранённые изменения. Перейти на другую страницу без сохранения?»

Для выхода из формы без сохранения необходимо подтвердить переход. Введённые данные будут потеряны. Для продолжения заполнения формы необходимо отменить переход.

Сочетания Alt + M и Alt + P определяются по расположению клавиш на клавиатуре и работают при русской и английской раскладке.

Приложение проверяет корректность календарных дат и их взаимное расположение:

  • дата рождения не может быть позже текущей даты;
  • дата приёма не может быть раньше даты рождения;
  • дата лабораторного или инструментального исследования не может быть позже даты приёма;
  • дата следующего контроля не может быть раньше даты приёма;
  • дата следующего контроля не может быть раньше текущей даты.

В зависимости от выявленной ошибки отображается одно из сообщений:

  • «Некорректная дата»;
  • «Дата рождения не может быть в будущем»;
  • «Дата приёма не может быть раньше даты рождения»;
  • «Дата исследования не может быть позже даты приёма»;
  • «Дата следующего визита не может быть раньше даты приёма»;
  • «Дата следующего визита не может быть раньше текущей даты».

Если при попытке сохранить приём в форме остаются ошибки:

  • отправка формы отменяется;
  • медицинская запись не создаётся;
  • в верхней части формы появляется сообщение о первой найденной ошибке;
  • страница автоматически прокручивается к первому полю с ошибкой;
  • курсор устанавливается в это поле.

Ранее введённые значения остаются в форме. После исправления ошибки необходимо повторно выполнить сохранение. Перед записью данных в базу приложение повторно проверяет введённые значения на сервере.

Для сохранения заполненной формы необходимо нажать кнопку «Сохранить прием» в нижней части страницы. Приём также можно сохранить сочетанием Ctrl + Enter. В обоих случаях выполняется одинаковая проверка обязательных полей, числовых значений, дат и зависимых полей.

При сохранении первичного приёма нового пациента приложение создаёт:

  • запись пациента;
  • электронную медицинскую карту;
  • медицинскую запись первого приёма;
  • результаты лабораторных и инструментальных исследований;
  • расчётные показатели;
  • диагнозы;
  • медикаментозная терапия;
  • диету и рекомендации.

При сохранении повторного приёма создаётся новая медицинская запись, связанная с его электронной медицинской картой. Ранее сохранённые приёмы не изменяются. После успешного сохранения открывается электронная медицинская карта пациента. В истории приёмов автоматически выбирается только что созданная медицинская запись.

При сохранении с помощью горячих клавиш кнопка отправки блокируется на время обработки запроса. Повторное нажатие сочетания до завершения сохранения не создаёт второй приём. На экране отображается сообщение: «Приём уже сохраняется».

Для одновременного сохранения приёма и скачивания консультативного заключения используется сочетание: Ctrl + Shift + Enter.

После нажатия приложение:

  1. Проверяет форму.
  2. Сохраняет медицинскую запись.
  3. Открывает электронную медицинскую карту пациента.
  4. Выбирает сохранённый приём.
  5. Автоматически запускает скачивание консультативного заключения в формате DOCX.

Если в форме обнаружена ошибка, сохранение не выполняется и документ не скачивается.

При обычном нажатии кнопки «Сохранить прием» или использовании Ctrl + Enter автоматическое скачивание не запускается. После сохранения документ можно скачать из электронной медицинской карты пациента.
